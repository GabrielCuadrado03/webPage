2. ESTRATEGIA DE RAMAS GIT Y FLUJO DE TRABAJO (¡MUY IMPORTANTE!)
================================================================================
El repositorio maneja 3 ramas con responsabilidades muy claras:

1) `main` (PRODUCCIÓN EN VIVO):
   - Lo que está publicado en internet (Firebase Hosting: ethereal-vapes.web.app).
   - Tiene despliegue automático (CI/CD) mediante `.github/workflows/firebase-hosting-merge.yml`.
   - Contiene: La tienda estable con colores/estilos originales, Barra de Anuncios en vivo,
     Code Splitting con React.lazy, Meta Tags OpenGraph, y el Panel Admin ERP modular
     con Notificaciones Telegram/Discord.
   - NO contiene el módulo confidencial Master Admin todavía.

2) `develop` (DESARROLLO Y PRUEBAS CONTINUAS — RAMA ACTUAL DE TRABAJO):
   - Creada desde `main` con todas las mejoras recientes + este archivo de contexto.
   - Aquí se deben programar, probar e integrar nuevas funcionalidades antes de
     hacer merge hacia `main`.

3) `moduloadministradorglobal` (MÓDULO MASTER ADMIN AISLADO):
   - Contiene el módulo confidencial de parametrización global completa:
     * Rutas secretas: `/master-control-88` y `/master-admin`
     * Archivo principal: `src/modules/master/MasterDashboard.jsx` + `README.md`
     * Theming dinámico en tiempo real vía CSS Variables (`src/utils/themeHelper.js`)
     * Passkey de acceso maestro (default: `master2026!`)
     * Backup / Restore de configuración en JSON.
   - NOTA IMPORTANTE DE MERGE: La rama `moduloadministradorglobal` fue creada ANTES
     de la refactorización modular de `AdminDashboard.jsx`, `AppRoutes.jsx` (lazy)
     y del servicio `orderNotifier.js` realizados en `main`/`develop`. Si en el futuro
     se decide fusionar `moduloadministradorglobal` con `develop`/`main`, se deberá
     resolver el merge cuidadosamente conservando la modularización de `AdminDashboard`
     y `orderNotifier.js`, y sumando `src/modules/master/`, `themeHelper.js` y
     las rutas del Master en `AppRoutes.jsx`.

4. BASE DE DATOS CLOUD FIRESTORE (COLECCIONES Y ESQUEMAS)
================================================================================
- `products`: { name, description, price, userDiscount, stock, imageUrl, categoryId, isFeatured, isAvailable }
- `combos`: { name, description, specialPrice, imageUrl, isAvailable, productIds: string[] }
- `categories`: docId = slug (ej. "pods"), { name, imageUrl }
- `banners`: { title, subtitle, description, imageUrl, linkText, linkUrl }
- `orders`: {
    customerId, totalAmount, itemsCount, createdAt (serverTimestamp),
    status ('pendiente' | 'confirmado' | 'entregado' | 'completado' | 'cancelado'),
    paymentMethod ('transferencia' | 'efectivo'),
    productsPurchased: string[],
    items: [{ productId, name, price, quantity, isCombo, productIds }],
    customerName, customerPhone, customerAddress,
    acceptedBy?, processedAt?, deliveredAt?, cancelledAt?
  }
  * NOTA: Confirmar un pedido (`confirmOrder` en AdminDashboard) ejecuta un `runTransaction`
    atómico que verifica stock de productos individuales y componentes de combos antes
    de descontar e insertar registros en `inventory_logs`.
- `inventory_logs`: { productId, productName, changeAmount, previousStock, newStock, adjustedBy, timestamp, reason }
- `users`: { uid, name/displayName, email, phoneNumber, createdAt, isAdmin (boolean), favoriteProductIds, addresses }
- `settings/general`: Documento singleton público para configuración en vivo (actualmente `announcementBar`).
- `settings/notifications`: Documento separado exclusivamente para ajustes y credenciales de
  alertas (`telegramEnabled`, `telegramBotToken`, `telegramChatId`, `discordEnabled`,
  `discordWebhookUrl`, `browserPushEnabled`, `browserSoundEnabled`).
  * Se separó intencionalmente de `settings/general` para que el Bot Token de Telegram
    NO se guarde en `localStorage` ni se descargue en la página de inicio para todos los visitantes.

5. RENDIMIENTO Y CODE SPLITTING IMPLEMENTADO
================================================================================
- `AppRoutes.jsx` usa `React.lazy()` para `AdminDashboard`, `Profile`, `Cart`, `Combos`, `Products`,
  `Login`, `Register` y `ForgotPassword`, envueltos en `<Suspense>`.
- Como `AdminDashboard` está protegido por `<PrivateAdminRoute>`, los clientes comunes NUNCA
  descargan el código JavaScript del ERP administrativo.
- `vite.config.js` separa en `manualChunks` los paquetes `react-vendor` y `firebase-vendor`.
- En compilación verificado: bundle inicial bajó de ~1,128 KB a ~288 KB (85 KB gzip).

6. SISTEMA DE NOTIFICACIONES PUSH / WEBHOOKS (`src/services/orderNotifier.js`)
================================================================================
- Al confirmar un pedido real en `Cart.jsx` (`handleCheckout`), se llama asíncronamente
  (sin bloquear la UI) a `getNotificationSettings()` y `notifyNewOrder(orderDoc, orderId, cfg)`.
- Canales soportados:
  1. Telegram Bot API: Envía mensaje HTML con ID de pedido, nombre, enlace `https://wa.me/...`,
     dirección, método de pago, lista de ítems y total. Listo para usar configurando Token
     y Chat ID desde `/admin` -> pestaña "Notificaciones".
  2. Discord Webhook: Preparado con payload Embed completo (`buildDiscordOrderPayload` +
     `sendDiscordNotification`). Solo requiere pegar la URL del Webhook y activar el switch.
  3. Navegador en vivo (cuando `/admin` está abierto): Sonido con Web Audio API
     (`playOrderAlertSound`) + notificación nativa del navegador (`showBrowserPushNotification`).
